# 安全与恢复规范

## 威胁模型

插件会修改用户源码、监听本地网络、采集运行时值并结束或启动进程。任何错误都可能造成源码污染、服务中断、凭据泄露或局域网数据暴露，因此安全行为必须由执行操作的模块强制，而不是只依赖提示词。

## 源码安全

- Instrumentation manifest 在第一次写源码前原子提交。
- 每个生成节点包含 run ID；清理只处理相同 ID。
- 保存原始内容用于人工恢复和差异展示，不作为默认整文件回滚手段。
- 当前文件 hash 与应用后 hash 不一致时进入 drift 路径。
- Drift 路径必须重新解析并删除精确生成节点；无法证明安全时停止并报告。
- 备份和运行资料使用当前用户权限，默认不离开本机。

## 日志安全

- 默认采集控制流和有限局部变量，不遍历全局对象。
- 在持久化和返回模型之前执行同一套脱敏。
- 默认敏感键模式覆盖 secret、token、password、authorization、cookie 和 key，允许部署方增加规则但不能关闭基础规则。
- 限制对象深度、属性数量、字符串长度、事件大小、每 probe 命中数、全局速率和磁盘总量。
- 遇到循环、getter 抛错或不可序列化值时记录占位事实，不执行危险 getter 或自定义序列化代码。

## Listener 安全

- 端口由 OS 分配，运行 token 使用密码学安全随机数。
- Token 不写入普通日志，不通过 query 列表或 UI 历史重复显示。
- Listener 只接受预期方法和 content type，执行 body、连接、速率和队列限制。
- 绑定所有网卡是 LAN fallback 所需能力；随机 token、无凭据 CORS 和短运行生命周期是补偿控制。
- HTTPS 页面到本机 HTTP 被浏览器阻止时报告限制，不指导用户关闭全局浏览器安全设置。

## 进程安全

- 插件启动的进程由插件直接拥有和结束。
- 外部现有进程必须同时匹配 workspace、launch spec 或明确用户选择。
- 结束前展示 PID、命令、cwd、端口和恢复方法并等待确认。
- 没有可靠恢复命令时不得宣传可以自动恢复；必须先让用户补充或选择启动项。
- 优雅结束失败后才允许强制结束，并在结果中记录升级事实。
- 不结束 Harness 自身、其祖先进程、操作系统关键进程或 workspace 之外的模糊候选。

## Flutter 临时配置

- Android 和 Apple 平台配置使用唯一 run marker。
- 只添加局域网日志所需最小权限或例外。
- 清理遵守与源码相同的版本漂移规则。
- Flutter Web mixed-content 不通过全局关闭安全机制解决。

## 崩溃恢复

- 运行目录记录最后完成的提交点和资源状态。
- 重启后扫描未完成运行，但不自动改写用户源码。
- 可验证生成节点可以通过显式恢复操作移除。
- 无法验证的文件、进程和配置逐项列出，并提供备份位置和手工恢复步骤。
